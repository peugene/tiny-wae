Fiche chapeau : elle ne se dispatche PAS. Elle porte le contexte et les décisions communes ; l'implémentation vit dans les sous-tâches. Le chapeau passe en fait/ quand toutes ses sous-tâches y sont.

⭐ Grain du graphe (décision Philippe E-c, 21/08) : un chapeau a depends_on: [] — il n'ordonne rien. Le tri topologique du run porte sur les seules fiches dispatchables (ni chapeau, ni humain) : toutes les vraies arêtes vivent dans les sous-tâches. Une fiche humain, elle, porte bien un depends_on et bloque volontairement ses dépendants. Un depends_on est satisfait quand la fiche visée est en fait/ — pas d'autre critère (le dossier fait foi). Motif : la lecture au grain chapeau bloquait tout l'aval derrière le gate humain de l0-03.H, y compris des fiches sans rapport (bornes de dates, CWL).

Contexte

Tout le pipeline aval consomme une configuration qui doit avoir UN propriétaire : les 25 sites (avec tuile de référence et grille figée), les réglages applicatifs, la taxonomie CLI et les codes de sortie. Réécrit en v3 post-revues (GO Philippe G1-G10 + D-a/D-b/D-c du 21/08) : voir _roadmap.md §1 pour les décisions actées, _revue-v2.md pour les findings.

Décisions portées par ce chapeau (rappel, ne pas rouvrir)

  • C08 = forêt de Bouconne (43.628, 1.217) — GO Philippe 21/08.
  • D-c : tuile de référence = celle qui donne la marge géométrique maximale au chip (distance chip↔bord de tuile) ; majorité d'items en départage. (La règle « majoritaire » seule choisissait la mauvaise tuile sur C07 : 52TDL marge 500 m vs 52TEL 4 160 m — mesuré.)
  • Grille par site : EPSG de la tuile de référence, origine = coin haut-gauche du chip calé sur multiple de 20 m. Bandes 60 m exclues du lot (fenêtre non entière — documenté).
  • Codes de sortie figés pour TOUS les CLIs : 0 succès · 1 échec métier · 2 erreur config/usage · 3 non concluant (amont injoignable). ⭐ Le code 3 est OBLIGATOIRE dans les trois CLIs qui appellent l'amont — ingest, backfill, update : un earth-search indisponible en pleine campagne doit se distinguer d'un échec métier (sinon une panne de service se lit comme un bug du pipeline). Règle : ≥ 1 item en échec réseau et 0 succès → 3 ; mélange succès/échecs → 1.
  • Auto-découverte CLI : un module par commande dans cli/, __main__.py jamais modifié après l0-01.2. Taxonomie fermée : 9 sous-commandes — version (existante), sites-validate, sites-list, search, ingest, backfill, update, report, contact-sheet. ⚠ smoke n'en fait PAS partie : c'est un script (scripts/smoke.py, lancé par just smoke), au même titre que record_fixtures.py et survey_tiles.py — pas un module de cli/. Le confondre ferait chercher un point d'entrée qui n'existe pas.
