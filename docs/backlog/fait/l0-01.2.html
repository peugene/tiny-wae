Objectif

Le mécanisme qui rend les fiches aval parallélisables : chaque commande = un module déposé dans cli/, découvert automatiquement — __main__.py n'est plus jamais modifié ensuite.

Périmètre (fichiers nommés)

  • src/tiny_wae/__main__.py : boucle d'enregistrement (import des modules de cli/ exposant app ou register(app) — choisir UNE convention et la documenter dans le docstring). La commande version existante survit.
  • src/tiny_wae/cli/exit_codes.py : constantes figées OK=0, FAILURE=1, USAGE=2, INCONCLUSIVE=3 — TOUS les CLIs du lot les importent (décision chapeau l0-01).
  • src/tiny_wae/cli/sites_validate.py et cli/sites_list.py : wiring pur sur la validation de l0-01.1 ; --json pour sites-list ; logs STDERR.
  • Taxonomie documentée (9 sous-commandes, cf. chapeau — smoke n'en est PAS une, c'est un script) : les 6 restantes n'existent PAS encore (pas de stubs) — la liste vit en commentaire dans __main__.py.

⚠ Ancrage dans le code réel (vérifié le 21/08/2026, base 061db8f)

Vérifié dans le code, pas supposé :

  • src/tiny_wae/__main__.py existe : app = typer.Typer(no_args_is_help=True, help=…), un callback @app.callback() def _main() indispensable (sans lui typer replie une app à commande unique et version deviendrait la commande racine — le docstring le dit), et @app.command() def version() qui écho tiny_wae.__version__, valeur réelle "0.1.0" (O4 confirmé). ⚠ L'auto-découverte doit préserver ce callback ET la commande version.
  • src/tiny_wae/cli/__init__.py existe (docstring seule) — c'est le package à balayer.
  • API réelle de l0-01.1, à câbler telle quelle : adapters.config_io.load_sites(path: Path = DEFAULT_SITES_PATH) -> list[Site], adapters.config_io.load_settings(...), core.sites.validate_sites(sites: list[Site]) -> None.
  • ⚠ DEUX exceptions à mapper sur USAGE=2, pas une : core.sites.SiteValidationError (validation) et adapters.config_io.ConfigError (chargement : fichier absent, champ inconnu, valeur env non convertible). N'en attraper qu'une laisserait O3 rouge sur la moitié des configs cassées.
  • O3 est déjà satisfaisable sans retoucher l0-01.1 : les messages de SiteValidationError nomment le site et le champ (f"site {self.id} : lat={self.lat} hors bornes …"). L'assertion portera sur ces deux chaînes littérales, pas sur une reformulation.

Décisions prises à l'ancrage (la fiche laissait explicitement le choix) :

  1. Convention d'enregistrement : register(app: typer.Typer) -> None exposée par chaque module de cli/ — retenue plutôt qu'un attribut app, parce qu'elle couvre aussi bien une commande simple qu'un sous-groupe et laisse le nom de la commande au module (sites-validate, tiret compris, que le nom de fonction Python ne peut pas porter).
  2. La fonction de découverte prend le package en paramètre (défaut tiny_wae.cli). C'est ce qui rend O1 testable proprement : le test crée un package temporaire et le passe en argument, au lieu de déposer un fichier dans le src/ installé puis d'espérer le nettoyer.
  3. Fixture de config cassée → tests/fixtures/config/ : tests/fixtures/ est une zone partagée (l0-02.1 → stac/, l0-03.2 → manifests/, l0-03.5 → cog/), on reste dans son sous-dossier.

Zone d'écriture EXCLUSIVE de cette fiche — 3 agents travaillent en parallèle sur N1 : src/tiny_wae/__main__.py, src/tiny_wae/cli/**, tests/test_cli*.py, tests/fixtures/config/. ⛔ Ne toucher NI core/ (l0-03.1 en parallèle), NI adapters/ (l0-03.2 en parallèle), NI pyproject.toml, justfile, config/, tests/test_config.py.
