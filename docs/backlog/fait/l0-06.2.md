   antérieures étaient fausses. Le protocole exact : (1) `ingest --site A01 --from J−20
   --to J−1` sur un `data_root` **vierge** ; (2) `cwltool update.cwl` — 1er run ; (3)

### `successCodes: [0, 1]` — et pourquoi

Même raisonnement qu'`ingest.cwl`, documenté dans le README : `FAILURE=1` recouvre à la fois
un échec métier classique **et** le site vierge (qui renvoie vers `backfill`). Sur un run
quotidien planifié, les deux sont des résultats légitimes, pas des incidents d'exécution —
l'idempotence `grid_hash` rattrapera au run suivant. `USAGE=2` et `INCONCLUSIVE=3` restent
des échecs CWL : une config invalide ou un amont mort doivent, eux, faire échouer le tool.
