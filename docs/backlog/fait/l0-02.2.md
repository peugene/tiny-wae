### Décisions d'ancrage (prises ici — ne pas rouvrir, ne pas re-délibérer)

1. **Point de couture pour l'injection de fixtures (décision D-a du chapeau).**
   `cli/search.py` expose `def build_source(settings: Settings) -> StacSource` qui retourne
   `EarthSearchSource(settings)` ; les tests monkeypatchent
   **`tiny_wae.cli.search.build_source`**. ⛔ **Ne PAS créer de `FixtureSource` dans `src/`** :
   le double de test vit dans `tests/`. La vraie `FixtureSource` est le périmètre de l0-03.5 —
   en poser une ici produirait deux classes homonymes.
2. **`INCONCLUSIVE=3` a besoin d'une exception typée, qui N'EXISTE PAS encore.**
   `EarthSearchSource.search` n'enveloppe aujourd'hui aucune erreur de transport (`Client.open`
   et l'itération des items remontent brut). Ajouter dans `adapters/stac.py` :
   `class StacUnreachable(Exception)` — ⚠ **héritant d'`Exception`, PAS de `StacSourceError`**
   (qui est un `ValueError` de parsing → `FAILURE` : sémantique opposée, un héritage ici
   ferait remonter un endpoint mort en « échec métier »). `search` attrape
   `(pystac_client.exceptions.APIError, OSError)` et relève
   `StacUnreachable(f"{settings.stac_url} injoignable : {exc}")`.
   ⚠ **Ne PAS attraper `RuntimeError`** : `pytest_socket.SocketBlockedError` en dérive
   (vérifié : MRO = `SocketBlockedError → RuntimeError`), l'attraper transformerait toute
   fuite réseau d'un test en un exit 3 vert-sur-du-faux.
   **Mapping du CLI** : `StacUnreachable → 3` · `StacSourceError → 1` · `ConfigError` /
   `SiteValidationError` / site inconnu / dates malformées → `2`.
3. **Discipline des flux (à tester, pas seulement à écrire)** : enveloppe JSON sur STDOUT
   (`json.dumps(envelope.to_dict())`) **ou** dans le fichier `--json <path>` ; dans ce
   dernier cas **STDOUT reste vide**. La table lisible et toute erreur partent sur STDERR.
   Rien d'autre ne s'écrit jamais sur STDOUT.
4. **Fenêtre** : `--from` / `--to` en `YYYY-MM-DD`, convertis en `datetime` naïfs et passés
   à `core.windows.Window(start=…, end=…)` (type déjà figé). `EarthSearchSource` transmet
   déjà des `datetime` à pystac-client — earth-search **rejette une plage date seule** (400,
   mesuré en l0-01.3) : ne pas repasser à des chaînes.
5. **O4 (live, hors gate)** : lancer à la main `just run search --site A01 --from 2022-09-01
   --to 2022-10-01`, relever le nombre d'items et le reporter dans le résumé de réalisation.
   Ce n'est PAS un test pytest (le gate reste hors ligne) — si le réseau est indisponible au
   moment du run, le noter comme **non mesuré** plutôt que d'inventer un chiffre.
