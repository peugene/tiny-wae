[l0-03.3] — Chips : lecture et écriture

Objectif

Depuis une Acquisition : lire les fenêtres nécessaires (SCL d'abord), écrire les 3 fichiers sur la grille du site. Pas de CLI ici (l0-03.4), pas de manifeste (fonction pure retournant un résultat que l0-03.4 assemble).

Périmètre (fichiers nommés)

  • src/tiny_wae/adapters/chips.py :
  • read_scl(acq, grid) -> ndarray 256×256 — fenêtre dérivée ici de core.geometry.chip_bounds (l0-03.1) via rasterio.windows.from_bounds sur le transform de la source ; Resampling.nearest si jamais nécessaire — normalement AUCUN rééchantillonnage, fenêtre entière.
  • read_bands_10m(acq, grid), read_bands_20m(acq, grid) — 4 et 6 bandes (D-b : rededge1/2/3 + nir08 + swir16 + swir22), dans CET ordre, gravé en constante BAND_ORDER_10M / BAND_ORDER_20M (l'ordre des bandes est un contrat du Lot 1).
  • write_chips(dest_dir, arrays, grid) : GeoTIFF simple, PAS COG (G5), uint16, transform de core.geometry.transform_for, tags (item_id, band order).
  • Garde : acq.proj_epsg == grid.epsg sinon exception typée (→ failed/tile_mismatch dans l0-03.4). ⭐ Compteur assets_read exposé (décision E-d) : nombre d'ouvertures de raster effectuées par ce module — l'instrument d'idempotence du lot. Pas de comptage d'octets ici (les lectures passent par GDAL, non instrumentable).
  • ⭐ Garde réseau de contrat (décision E-b, 21/08) : sous TINY_WAE_OFFLINE=1, refuser tout href dont le schéma n'est pas file:// → exception typée RemoteAccessForbidden, levée AVANT toute ouverture (aucune requête émise). C'est ICI qu'elle vit — chips.py est le seul point qui ouvre les rasters ; la placer dans FixtureSource seul serait contournable. ⚠ Motif mesuré en revue v3 : pytest-socket ne couvre PAS les lectures GDAL (C/libcurl), donc une garde de transport laisserait passer un smoke « vert en téléchargeant ».
  • Dépendance utilisée : rasterio — déjà posée par l0-01.1 (ne pas toucher au pyproject.toml). pixi.lock : versionné, jamais mergé — régénérer au besoin.
  • Tests : sur les GeoTIFF fixtures locaux de l0-03.5 s'ils existent déjà, SINON sur des rasters synthétiques écrits par le test (les deux marchent — ne pas attendre l0-03.5).

Décisions d'ancrage (prises ici — ne pas rouvrir, ne pas re-délibérer)

  1. Forme du retour (contrat vers l0-03.4) : adapters/chips.py expose un dataclass frozen=True, slots=True nommé ChipResult, portant au moins files: list[str], assets_read: int, content_hashes: dict[str, str], bytes_written: int, chip_nodata_pct: float — noms alignés sur Manifest (voir ci-dessus).
  2. assets_read remonte PAR VALEUR DE RETOUR, jamais par un compteur de module : ⛔ aucun global mutable — l0-04.1 fera tourner plusieurs ingestions dans un pool de workers, un compteur de module y serait faux silencieusement. Chaque read_* renvoie son nombre d'ouvertures avec son tableau ; l0-03.4 les somme.
  3. scl_class_counts n'est PAS du périmètre de cette fiche : read_scl renvoie le ndarray ; le comptage des classes et l'appel à core.scl.verdict restent à l0-03.4.
  4. Unité de chip_nodata_pct : un POURCENTAGE (0–100), pas une fraction 0–1 — même unité que settings.chip_nodata_pct_max (défaut 1) et que l'oracle O3 (« 0,5 % → ingested ; 40 % → rejected_nodata »). Valeur nodata = 0 (convention S2 L2A) ; la fraction se mesure sur le chip 10 m.
  5. Garde réseau TINY_WAE_OFFLINE : nom EXACT de la variable d'environnement (aucune variante), active quand elle vaut "1". RemoteAccessForbidden est levée avant toute ouverture (aucune requête émise, pas même une sonde). ⚠ Schémas acceptés : file:// et un chemin nu sans schéma (/…/x.tif — c'est la forme que prendront les fixtures locales de l0-03.5, et rasterio les ouvre telles quelles). Refusés : http://, https://, s3://, et tout autre schéma. Écrire ce choix en docstring : la fiche dit « schéma != file:// », le chemin nu en est l'extension nécessaire.
  6. Écriture : GeoTIFF simple, PAS COG (G5) ; uint16 pour les bandes, uint8 pour le SCL ; transform_for(grid, 10) / transform_for(grid, 20) ; CRS = EPSG:{grid.epsg} ; tags item_id + ordre des bandes. Noms de fichiers figés : chip.tif, chip_20m.tif, scl.tif.
  7. Hash de contenu (O1bis) : sha256 sur array.tobytes() + f"EPSG:{grid.epsg}" + les 6 coefficients du transform formatés + array.dtype.str. ⛔ Jamais les octets du fichier GeoTIFF (le WKT PROJ embarqué dérive entre versions et plateformes — l'oracle deviendrait un détecteur de version de GDAL).
  8. Tests sur rasters synthétiques (l0-03.5 n'existe pas encore) : le test écrit lui-même ses GeoTIFF sources avec rasterio, sur une grille et un EPSG connus, avec des valeurs de pixels choisies — c'est ce qui rend O1 discriminant (valeur attendue au pixel près, pas seulement une forme de tableau).

Décisions prises en cours de réalisation

  1. settings ajouté en 3ᵉ paramètre des read_* — la fiche écrivait read_scl(acq, grid), mais chip_bounds(grid, settings) a besoin des tailles de chip. Nécessaire, pas cosmétique.
  2. ⭐ Convention nodata (décision produit, à connaître) : un pixel du chip 10 m n'est compté nodata que si les 4 bandes y valent 0 — pas si une seule vaut 0. Motif : sur S2 L2A une bande isolée à 0 est une valeur légitime (surface très sombre en SWIR), alors que hors emprise toutes les bandes tombent à 0. La convention inverse sur-compterait le nodata et déclencherait des rejected_nodata fantômes.
  3. Forme (bands, H, W) et files en noms relatifs ("chip.tif"), pas en chemins absolus.

⚠ À traiter par l0-03.4 (relevé à la revue du diff, non corrigé ici)

check_epsg lève EpsgMismatchError aussi quand grid.epsg is None (grille non calculée), avec un message « … != grid.epsg=None ». Le diagnostic est alors trompeur : la cause n'est pas un item non superposable (→ statut failed) mais une config incomplète (→ exit USAGE, just survey-tiles à lancer). l0-03.4 doit distinguer les deux cas au moment où il mappe les exceptions sur les statuts et les codes de sortie. Non corrigé ici : le chemin est protégé en amont par l'ordre invariant du chapeau, et la grille est remplie 25/25 depuis l0-01.3 — c'est un défaut de diagnostic, pas de correction.
