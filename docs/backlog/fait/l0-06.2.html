successCodes: [0, 1] — et pourquoi

Même raisonnement qu'ingest.cwl, documenté dans le README : FAILURE=1 recouvre à la fois un échec métier classique et le site vierge (qui renvoie vers backfill). Sur un run quotidien planifié, les deux sont des résultats légitimes, pas des incidents d'exécution — l'idempotence grid_hash rattrapera au run suivant. USAGE=2 et INCONCLUSIVE=3 restent des échecs CWL : une config invalide ou un amont mort doivent, eux, faire échouer le tool.
