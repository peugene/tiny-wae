# [l0-03] — CHAPEAU : Ingestion des chips

> Fiche chapeau, non dispatchable, `depends_on: []` (E-c : un chapeau n'ordonne rien).
> **Vient après l0-02** — les arêtes réelles sont portées par les sous-tâches. La v2 avait
> tout mis dans une seule fiche — la revue v2 l'a retoquée (récidive du défaut l0-04).
> Découpée en 7 sous-tâches agent (S/M) + 1 fiche HUMAINE.

## Contexte

Pour (site, Acquisition) : produire chips 10 m + 20 m + SCL + manifeste, ou rejeter
proprement. Clé de stockage = **item id** (G9). Grille du site = superposition au bit près
(G8/D-c). Le smoke remplace le placeholder et doit rester déterministe (D-a).

## Décisions portées (ne pas rouvrir)

- Sorties par item : `<data_root>/{site_id}/{item_id}/` → `chip.tif` (512×512×4 @ 10 m :
  blue/green/red/nir, **GeoTIFF simple, pas COG — G5**), `chip_20m.tif` (256×256×**6** @
  20 m : rededge1/rededge2/rededge3/nir08/swir16/swir22 — **D-b**, Clay v1.5 nominal,
  coût total ×1,41), `scl.tif` (256×256 @ 20 m), `manifest.json`.
- Ordre invariant : garde epsg (item.proj_epsg == grid.epsg, sinon `failed`) → SCL seul
  (fenêtré) → verdict (`invalid_pct` {0,1} > invalid_pct_max → `rejected_invalid` ;
  `cloud_pct` {3,8,9,10} > cloud_pct_max → `rejected_clouds` ; classes 2 et 11 comptées,
  décision différée documentée) → bandes 10 m puis 20 m → ⭐ **garde nodata FINALE**.
  SCL rééchantillonné JAMAIS (verdict calculé à 20 m sur 256×256).
- ⭐ **Garde nodata instrumentée (arbitrage n°3, 21/08)** — le GO **G8** exigeait « tuile
  de référence **+ garde nodata** » et `lot-0-sites.md` O3 « nodata < 1 % sur 100 % des
  ingested », mais rien ne la portait : `s2:nodata_pixel_percentage` est une métrique de
  **scène** (110 km), inutilisable pour un chip de 5 km. Désormais : `chips.py` mesure la
  fraction de pixels nodata **du chip produit** (`chip_nodata_pct`), elle est **écrite au
  manifeste**, et si elle dépasse `chip_nodata_pct_max` (settings, défaut 1 %) l'item
  prend le statut **`rejected_nodata`** — les fichiers écrits sont supprimés. Cas visé :
  chip en bord de fauchée ou hors emprise de la tuile épinglée (mesuré : 8 items sur 636
  ont > 50 % de nodata scène sur C07).
- **D-a** : rejeu = GeoTIFF locaux clippés versionnés (`tests/fixtures/cog/`) +
  `FixtureSource` implémentant le port `StacSource` + assets `file://`. Aucun mock HTTP.
  Horloge injectable (`--now`).
- ⭐ **E-b (21/08) — la garde réseau est une garde de CONTRAT, pas de transport** : sous
  `TINY_WAE_OFFLINE=1` (posé par `smoke --replay`, hérité par `just check`),
  `adapters/chips.py` refuse tout href non-`file://` → `RemoteAccessForbidden`, levée
  avant ouverture. Mesuré en revue v3 : `pytest-socket` ne couvre PAS les lectures GDAL
  (C/libcurl) — une garde de transport laisserait un smoke passer **vert en
  téléchargeant** (faux-vert). `pytest-socket` reste en ceinture pour le seul chemin
  STAC (httpx/pystac-client) — limite à écrire, pas à masquer.
- Idempotence au grain item **+ signature de grille** : le manifeste porte `grid_hash` ;
  si la signature du site a changé → l'item est RÉ-ingéré (l'impasse « chips
  inatteignables après correction de coordonnées » disparaît). `--force` disponible.
  ⭐ **Contenu et sérialisation du `grid_hash` (précision PO, 21/08)** :
  `sha256` d'une chaîne canonique `f"{epsg}|{int(origin_x)}|{int(origin_y)}|{chip_px_10m}|
  {chip_px_20m}|{','.join(BAND_ORDER_10M)}|{','.join(BAND_ORDER_20M)}"` — origines
  **normalisées en entiers** (`699960` et `699960.0` doivent donner le MÊME hash, sinon
  une relecture YAML déclenche une ré-ingestion fantôme de tout le parc). La signature
  **inclut les bandes et les tailles** : D-b vient de faire passer le chip 20 m de 3 à
  6 bandes, un tel changement DOIT invalider les chips existants.
- ⭐ **Instrumentation de l'idempotence (décision Philippe E-d, 21/08)** :
  - **`assets_read`** = nombre d'ouvertures de raster effectuées par `chips.py` (notre
    code compte ses propres appels : la mesure vaut à l'identique sous `file://` et
    `https://`). **C'est LE critère d'idempotence** du lot.
  - **`bytes_downloaded`** = octets HTTP reçus par le **client STAC Python uniquement** ;
    il **n'inclut PAS** les lectures d'assets par GDAL (non instrumentables depuis
    Python — mesuré en revue v3). C'est une **donnée de rapport, jamais un critère de
    gate**. Le volume réellement transféré en campagne se mesure au niveau système, ou se
    déclare non mesuré.
  - **Hashes de sortie = contenu DÉCODÉ** : `sha256(array.tobytes())` + CRS + transform +
    dtype — **pas** les octets du GeoTIFF (le WKT PROJ embarqué vient d'une base
    versionnée : un hash d'octets dériverait entre versions et entre `linux-64`/`win-64`).
  - Tout oracle d'idempotence porte un **témoin positif** (1er run : `assets_read > 0`)
    ET un **témoin négatif** (2e run : `assets_read == 0`).
  - **`--now` n'existe PAS sur `ingest`** (ses deux formes d'appel ont une fenêtre
    explicite : l'option serait morte) — il vit sur `backfill` et `update`, seuls à
    calculer des fenêtres relatives à maintenant.
- Item ids gelés : cf. chapeau l0-02.
