# [l0-02.1] — StacSource et contrat Acquisition

## Objectif

Le port, le contrat et son implémentation earth-search — testés sur fixtures des DEUX
générations d'items (S2A/B et S2C).

## Périmètre (fichiers nommés)

- `src/tiny_wae/core/acquisition.py` : dataclass frozen `Acquisition`. ⭐ **Champs exacts,
  avec leur CLÉ STAC SOURCE — à ne pas deviner** (relevé de la revue v3 ; noter que trois
  clés sont préfixées `s2:`/`earthsearch:`, ce dernier étant **propre à earth-search** et
  destiné à disparaître à une éventuelle bascule CDSE) :

  | champ | clé STAC source | remarque |
  |---|---|---|
  | `item_id` | `id` | |
  | `datetime` | `properties.datetime` | |
  | `platform` | `properties.platform` | `sentinel-2a/2b/2c` — **jamais déduit de l'id** |
  | `tile` | `properties.grid:code` | ex. `MGRS-31TGJ` |
  | `sequence` | `properties.s2:sequence` | ⚠ valeur = **chaîne** `"0"`, pas un entier |
  | `scene_cloud_cover` | `properties.eo:cloud_cover` | métrique **scène** (110 km) |
  | `nodata_pixel_pct` | `properties.s2:nodata_pixel_percentage` | métrique **scène** |
  | `processing_baseline` | `properties.s2:processing_baseline` | plusieurs valeurs coexistent dans la fenêtre (04.00 → 05.12, mesuré) |
  | `boa_offset_applied` | `properties.earthsearch:boa_offset_applied` | ⚠ **préfixe vendeur** |
  | `proj_epsg` | `properties.proj:epsg` | garde epsg de l0-03.3 |
  | `assets` | `assets[clé].href` | `dict[str, str]`, hrefs `https://` |
  | `radiometry` | `assets[clé].raster:bands[0].{scale,offset}` | ⭐ **dict PAR ASSET** (arbitrage n°1) |

- ⭐ **Arbitrage n°1 (21/08) — `raster:bands` est une propriété PAR ASSET, pas par item** :
  mesuré, les 10 bandes de réflectance portent `scale 0.0001 / offset −0.1`, mais `aot` et
  `wvp` portent `0.001 / 0` et `scl` n'en a **aucun**. Le contrat expose donc
  `radiometry: dict[str, tuple[float, float] | None]` (clé d'asset → scale/offset), pas
  deux scalaires. C'est la **traçabilité radiométrique promise au Lot 1** : un contrat
  lossy ici se paierait par une ré-lecture complète plus tard.
  Round-trip JSON de l'ensemble.
- `core/envelope.py` : l'enveloppe versionnée du chapeau (`schema_version=1`, counters,
  items) + round-trip. **Counters exacts** : `found_stac`, `skipped_scene_cloud`,
  `off_tile`, `found_tile` (cf. chapeau, décision E-a — le nom `found` seul est banni).
  L'enveloppe **vérifie elle-même** `found_stac == skipped_scene_cloud + off_tile +
  found_tile` et `found_tile == len(items)` à la construction (exception typée sinon).
- `src/tiny_wae/adapters/stac.py` : port `StacSource` (protocole : `search(site, window)
  -> Envelope`) + `EarthSearchSource` (pystac-client). Filtres : bbox du chip TOUJOURS +
  `eo:cloud_cover < scene_cloud_max` (compté `skipped_scene_cloud`) + tuile de référence
  (compté `off_tile`). **Garde href : pour les clés d'assets MAPPÉES uniquement, refuser
  tout `s3://`** (les assets non mappés des S2C sont ignorés sans erreur).
- Tests : fixtures enregistrées dans `tests/fixtures/stac/` — **cinq** : (1) l'item gelé
  `S2B_31TGJ_20230315_0_L2A`, (2) l'item S2C `S2C_31TGJ_20260513_0_L2A` (schéma d'assets
  différent), (3) un item `sequence=1` (candidat mesuré en revue v3 :
  `S2A_31TGJ_20260813_1_L2A`), (4) une réponse vide, (5) **une réponse bi-tuile sur C07**
  (bbox 129.0494,41.257,129.1106,41.303 — nécessaire à O4, seule fixture qui exerce
  `off_tile`).
- Dépendance utilisée : `pystac-client` — **déjà posée par l0-01.1** (ne pas toucher au
  `pyproject.toml`). `pixi.lock` : versionné, jamais mergé — régénérer au besoin.
