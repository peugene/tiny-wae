# [l0-02.2] — CLI search

## Objectif

Exposer la recherche en CLI, avec la discipline logs/données et la garde anti-réseau des
tests.

## Périmètre (fichiers nommés)

- `src/tiny_wae/cli/search.py` (auto-découvert, cf. l0-01.2) :
  `search --site A01 --from … --to … [--json out.json]` — table lisible sur STDERR,
  **enveloppe JSON sur STDOUT ou fichier** (rien d'autre sur STDOUT). Codes de sortie de
  `exit_codes.py` ; endpoint injoignable → `INCONCLUSIVE=3` (jamais confondu avec un bug).
- Garde anti-réseau des tests : `pytest-socket` + `--disable-socket` par défaut dans la
  config pytest — ⚠ **la dépendance et la configuration sont posées par l0-01.1** (avec
  toutes les autres, cf. geste PO « dépendances pré-posées ») ; cette fiche ne fait que
  les utiliser. ⚠ **Portée réelle (décision E-b) : le chemin STAC
  UNIQUEMENT** (`httpx`/`pystac-client`, qui passent par le `socket` Python). Elle **ne
  couvre PAS** les lectures rasterio/GDAL (C/libcurl) — celles-ci sont gardées par le
  contrat `TINY_WAE_OFFLINE` dans `chips.py` (l0-03.3). Écrire cette limite en commentaire
  de la config pytest, pour que personne ne croie qu'un seul dispositif suffit. Les
  oracles LIVE ci-dessous sont hors gate, lancés à la main avant livraison.
- Test de capture : STDOUT parse comme JSON seul ; les logs sont sur STDERR.

## Définition de « terminé »

- [ ] CLI branché, fixtures vertes sous `--disable-socket`, capture STDOUT/STDERR testée.
