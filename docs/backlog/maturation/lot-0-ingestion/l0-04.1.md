# [l0-04.1] — CLI backfill

## Objectif

Orchestrer `ingest` sur sites × fenêtres avec un pool borné. Zéro campagne réelle ici —
tout se teste sur FixtureSource.

## Périmètre (fichiers nommés)

- `src/tiny_wae/cli/backfill.py` (auto-découvert) : `backfill [--sites all|A01,B02]
  [--months N] [--workers N] [--now …]` — fenêtres via `core/windows.backfill_windows`,
  exécution par pool (`concurrent.futures`, défaut `backfill_workers` de settings),
  **un site = une unité d'isolation** (échec d'un site → les autres continuent, exit 1
  à la fin). Compteurs agrégés par site sur STDERR, `run.json` par (site, fenêtre) via
  l'API manifests. Réutilise le retry de l0-03.4 — AUCUN retry ici.
- **Interruption propre** : le gestionnaire de signal (SIGINT, et `CTRL_BREAK_EVENT` sur
  Windows) → arrêt des soumissions, attente des items en cours, exit ≠ 0 ; grâce à
  l'atomicité de l0-03.2, aucun manifeste tronqué. ⚠ **Le déclenchement du signal n'est
  PAS portable** (`pyproject.toml` cible `linux-64` ET `win-64`) : le test du gate
  appelle **directement le gestionnaire** (fonction pure d'arrêt), pas un vrai signal —
  l'interruption réelle est vérifiée à la main sur la campagne (l0-04.H).
- La source (Earth/Fixture) suit le même point d'injection que l0-03.4.

## Définition de « terminé »

- [ ] CLI + pool + isolation + SIGINT, tests sur FixtureSource (A01 × sept. 2022, 6 items).

## Oracle / recette

| # | Critère | Seuil |
|---|---|---|
| O1 | `backfill --sites A01 --months 1 --workers 4 --now <date de la fenêtre du corpus>` sur FixtureSource | même ensemble `(item_id, statut)` qu'un run `--workers 1` (déterminisme du pool) ; compteurs == valeurs gelées dans le test (A01 mono-tuile : `found_stac=6, skipped_scene_cloud=0, off_tile=0, found_tile=6`) ; **les deux invariants de conservation bouclent**. ⚠ `--now` est passé littéralement : la fenêtre du corpus est **absolue**, jamais « 48 mois glissants » |
