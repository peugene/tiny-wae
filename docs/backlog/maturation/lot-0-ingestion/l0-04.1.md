# [l0-04.1] — CLI backfill

## Objectif

Orchestrer `ingest` sur sites × fenêtres avec un pool borné. Zéro campagne réelle ici —
tout se teste sur FixtureSource.

## Périmètre (fichiers nommés)

- `src/tiny_wae/cli/backfill.py` (auto-découvert) : `backfill [--sites all|A01,B02]
  [--months N] [--workers N] [--now …]` — fenêtres via `core/windows.backfill_windows`,
  exécution par pool (`concurrent.futures`, défaut `backfill_workers` de settings),
  **un site = une unité d'isolation** (échec d'un site → les autres continuent, exit 1
  à la fin). Compteurs agrégés par site sur STDERR, `run.json` par (site, fenêtre) via
  l'API manifests. Réutilise le retry de l0-03.4 — AUCUN retry ici.
- **Interruption propre** : SIGINT → arrêt des soumissions, attente des items en cours,
  exit ≠ 0 ; grâce à l'atomicité de l0-03.2, aucun manifeste tronqué.
- La source (Earth/Fixture) suit le même point d'injection que l0-03.4.

## Définition de « terminé »

- [ ] CLI + pool + isolation + SIGINT, tests sur FixtureSource (A01 × sept. 2022, 6 items).

## Oracle / recette

| # | Critère | Seuil |
|---|---|---|
| O1 | `backfill --sites A01 --months 1 --workers 4 --now 2022-10-01` sur FixtureSource | même ensemble `(item_id, statut)` qu'un run `--workers 1` (déterminisme du pool) ; compteurs == valeurs gelées dans le test (A01 mono-tuile : `found_stac=6, skipped_scene_cloud=0, off_tile=0, found_tile=6`) ; **les deux invariants de conservation bouclent** |
| O2 | Échec injecté sur 1 site / 2 | l'autre site complet, exit 1, site fautif nommé |
| O3 | SIGINT en cours de run (test avec fixture ralentie) | exit ≠ 0 ; tous les manifestes présents relisibles (`read_manifest` OK sur 100 %) |
| O4 | Run double (E-d) | 1er run : `assets_read > 0` ; 2e run : `assets_read == 0`, 100 % skipped, `content_hashes` identiques |
| O5 | `just check` | vert, hors ligne |

**Non testé** : volumes réels et quotas (l0-04.H) ; le dimensionnement 4-8 workers
optimal (mesuré en campagne).
