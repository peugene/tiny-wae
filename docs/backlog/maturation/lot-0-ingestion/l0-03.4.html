[l0-03.4] — CLI ingest

Objectif

Assembler : recherche (ou liste fournie) → pour chaque item : garde → SCL → verdict → chips → manifeste. Relançable à l'infini.

Périmètre (fichiers nommés)

  • src/tiny_wae/cli/ingest.py (auto-découvert) : ingest --acquisitions <envelope.json> (chaînage CWL) ET ingest --site A01 --from … --to … (appelle StacSource). ⚠ PAS d'option --now (décision E-d : les deux formes portent une fenêtre explicite, l'option serait morte — --now vit sur backfill et update). Compteurs finaux sur STDERR (found_stac / skipped_scene_cloud / off_tile / found_tile puis ingested/rejected_*/skipped/failed + bytes + durée) ; run.json écrit via manifests API (les 4 compteurs de l'enveloppe y sont recopiés — cf. schéma l0-03.2, avec ses deux invariants de conservation).
  • Ordre invariant (chapeau) : garde epsg → SCL seul → verdict → bandes 10 puis 20 m → fichiers → manifeste (dernier, atomique). Un rejet écrit un manifeste SANS chips.
  • Idempotence : manifeste existant pour item_id ET grid_hash identique → skip compté. grid_hash différent (coordonnées corrigées) → ré-ingestion. --force → ré-ingestion inconditionnelle.
  • Retry/backoff au niveau requête (paramètres http_retries/http_backoff_s de settings) sur STAC et lectures COG ; échec définitif → manifeste failed + cause, JAMAIS d'exception avalée. Un item en échec n'arrête pas les suivants ; exit FAILURE=1 si ≥ 1 failed, sinon OK=0.

Définition de « terminé »

  • [ ] CLI 2 formes + idempotence + retry, tests sur FixtureSource (l0-03.5) ou doubles en mémoire du port StacSource.

Oracle / recette (sur fixtures — le live vit en l0-03.5)
