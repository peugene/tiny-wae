Objectif

Brancher Clay v1.5 derrière le port : un ChipTensor en entrée, un vecteur (1024,) en sortie — le CLS de l'encodeur.

Contexte et périmètre

src/tiny_wae/adapters/embed_clay.py — l'entrée du registre existe déjà (l1-01.3), tu n'écris QUE ce fichier et son test.

La recette, vérifiée au code source (24/08/2026) — suivre, ne pas redécouvrir

  1. Chargement : ckpt via hf_hub_download("made-with-clay/Clay", "v1.5/clay-v1.5.ckpt") (cache l1-00), puis ClayMAEModule.load_from_checkpoint(ckpt, model_size="large", mask_ratio=0.0, shuffle=False, metadata_path=<chemin ABSOLU du metadata.yaml embarqué>). - ⚠ mask_ratio=0.0 est LE point critique : le défaut est 0.75 et s'applique en inférence (mask_out inconditionnel) — sans cet argument, l'embedding ne voit que le quart bas de l'image et tous les tests passent quand même. ⚠ Précision revue v3 (A-3) : le tutoriel pose en réalité quatre arguments — mask_ratio=0.0, shuffle=False, plus dolls=[16, 32, 64, 128, 256, 768, 1024] et doll_weights=[1]*7. Comme les kwargs de load_from_checkpoint priment sur les hyperparamètres restaurés du ckpt, omettre dolls/doll_weights n'est neutre que si le ckpt v1.5 porte les mêmes valeurs : le vérifier après chargement et le consigner, plutôt que de le supposer. - ⚠ metadata_path : le défaut est relatif au CWD — passer un chemin absolu, sinon le CLI casse selon d'où on le lance. ⛔ « le résoudre depuis le paquet » est IMPOSSIBLE — vérifié le 26/08 : le paquet claymodel 1.5.0 ne contient aucun .yaml, le configs/metadata.yaml du dépôt Clay n'est pas packagé. Et claymodel/module.py:31 l'ouvre directement, sans repli (Box(yaml.safe_load(open(metadata_path)))) : sans fichier fourni par nous, load_from_checkpoint lève un FileNotFoundError quel que soit le CWD. C'est la fiche l1-08 qui l'embarque, et c'est pourquoi elle est désormais dans le depends_on de celle-ci (arête posée par l'équipe pendant le run de N0 — le PO peut la déplacer, mais pas la supprimer sans traiter le problème). - ⚠ save_hyperparameters() restaure les hyperparamètres du ckpt : vérifier APRÈS chargement que model.model.encoder.mask_ratio == 0.0 (assertion dans l'adapter).
  2. Normalisation : z-score sur DN — (pixels - mean) / std, stats de metadata.yaml (sentinel-2-l2a, blue: mean 1105., std 1809.), lookup par nom depuis BAND_ORDER_EMBED. Pas de réflectance.
  3. Datacube : {"pixels": …, "time": [B,4], "latlon": [B,4], "gsd": tensor(20.0), "waves": …} — time et latlon encodés comme dans le tutoriel embeddings (sin/cos de la semaine et de l'heure ; sin/cos de lat/lon) depuis chip.datetime et chip.lat/lon ; gsd=20 (le metadata dit 10, notre tenseur est à 20 — lui mentir fausserait l'encodage de position) ; waves en µm (l'unité du code d'entraînement), lookup par nom. ⭐ Fait vérifié au code source (revue v3, V-17) — conséquence lourde pour le Lot 2 : time vaut exactement np.hstack((week_norm, hour_norm)) (claymodel/datamodule.py, confirmé par le tutoriel : « time: batch x 4 — horizontally stacked week_norm & hour_norm »). Ni l'année, ni aucune époque absolue n'entre dans le modèle. Ce n'est donc pas la date qui est encodée, c'est la phase saisonnière : deux acquisitions à un an d'écart, à la même semaine, sont indiscernables pour le modèle sur ce canal — et deux dates de saisons différentes sont écartées par construction, ce qui est exactement le confondant que l1-05.4 cherche à isoler. À consigner au Résumé.
  4. Sortie : out = encoder(datacube) → tuple ; CLS = out[0][:, 0, :] → (1024,) float32.
  5. ⚠ L'import de claymodel exécute torch.set_float32_matmul_precision("medium") au niveau module — le consigner dans le Résumé (le banc lancera un processus par modèle).

Oracle / recette (figé AVANT implémentation)

# Critère mesuré Seuil de succès
O1 embed sur la fixture claire de l1-01.4 vecteur (1024,) float32, aucun NaN ni inf
O2 Deux appels, même ChipTensor, threads figés vecteurs identiques
O3 Deux fixtures différentes vecteurs distincts (témoin négatif)
O4 ⭐ Le masque est bien désactivé : nombre de tokens traversant l'encodeur, unmsk_patch.shape[1] == 1025 (1024 patchs + CLS — valeur re-vérifiée à la source). ⚠ Cette grandeur est interne à l'encodeur : elle n'est pas atteignable depuis le port, qui ne rend qu'un (1024,). L'assertion vit donc dans l'adapter, sur le tenseur intermédiaire assertion dans l'adapter + témoin : un test qui monkeypatche mask_ratio à 0.75 doit faire lever l'adapter (avec le masque, ce serait 257). Sans ce témoin, l'assertion est du code jamais exercé
O5 ⭐ Témoin spatial : la même fixture avec un quadrant mis à zéro vecteur différent — prouve que le modèle voit toute l'image (avec le masque par défaut, le quadrant haut-gauche est jeté et ce témoin échoue)
O6a Même chip, datetime décalé d'un an jour pour jour, dates gelées dans le test de façon à tomber sur la même semaine ISO vecteurs identiques. ⭐ C'est le constat, pas un objectif : l'encodage temporel de Clay ne porte pas l'année (voir §3). Le fait est consigné pour le Lot 2 — une dérive d'embeddings ne peut pas confondre « un an plus tard » avec « un changement », mais elle confond structurellement deux dates de même saison
O6b Même chip, datetime décalé d'environ six mois (p. ex. semaine 31 → semaine 5) vecteurs différents — c'est ce témoin qui prouve que la date entre réellement dans le modèle. (L'ancien O6, « +1 an → différents », était faux : il ne pouvait qu'échouer, ou passer par accident sur un basculement de semaine ISO.)
O7 import adapters.model_registry sans appeler Clay "torch" not in sys.modules (garde d'import paresseux, O4 de l1-01.3 toujours vert)
O8 just check vert, hors ligne (cache peuplé)
