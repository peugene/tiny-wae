# [l1-02.3] — La garde réseau des poids

> Fiche de backlog : sert de **brief (prompt)** pour l'IA.

## Objectif

Empêcher tout téléchargement de poids **pendant un run**. La carte du modèle TerraMind
l'annonce noir sur blanc : *« The weights are automatically downloaded from Hugging Face »*.
C'est précisément ce qu'on interdit.

## Contexte et périmètre

**Pourquoi ça compte, dans l'ordre de gravité :**

1. ⭐ **Un téléchargement au milieu d'un run chronométré fausse la mesure, et ça ne se voit
   pas.** Le banc rapporterait « 45 s par chip » au lieu de 3, on incriminerait le CPU, et
   le Lot 1 conclurait à un périmètre embeddable faux.
2. **Chaque worktree d'agent retéléchargerait.** Le Lot 0 a établi que les environnements ne
   se partagent pas entre worktrees. Trois agents en parallèle, trois téléchargements.
3. **Le gate deviendrait dépendant du réseau** — `just check` échouerait hors connexion.

À livrer, trois pièces :

- **Le cache local.** `HF_HOME` (ou `HF_HUB_CACHE`) pointé vers un répertoire **du projet**,
  gitignoré — par exemple `models/` — au lieu de `~/.cache/huggingface`. Tout atterrit au
  même endroit, partagé par les worktrees, visible, effaçable.
- **La recette de pré-chargement.** `just fetch-models` : la **seule** commande du projet
  autorisée à faire du réseau pour les poids. Lancée une fois, à la main. Même esprit que
  `just db` — de la préparation d'infrastructure, **hors du gate**.
- **La garde.** Au run, `HF_HUB_OFFLINE=1` est posé par le code lui-même. La bibliothèque
  refuse alors le réseau et lève si les poids manquent ; on rattrape l'erreur pour la
  réécrire en clair : *« poids `<model_id>` absents du cache — lance `just fetch-models` »*.

⭐ **Ce qu'on ne fait PAS : un test dédié à la garde.** Vider un cache, capturer une
exception, restaurer l'état — c'est de la machinerie qui coûte plus cher que ce qu'elle
protège. **On met le smoke SOUS la garde** : `scripts/smoke.py` (fiche `l1-03.4`) tourne avec
`HF_HUB_OFFLINE=1` posé. Si quelqu'un retire la garde ou casse le chemin du cache, le smoke
tombe — à chaque `just check`, gratuitement, sans une ligne de test dédiée.

C'est le pendant exact de `TINY_WAE_OFFLINE` posé par le smoke du Lot 0 (`l0-03.7`) : la
même idée, appliquée aux poids au lieu des rasters.

**Hors périmètre** : la garde rasterio/GDAL du Lot 0, qui reste en place et couvre un autre
chemin · toute mesure.

## Définition de « terminé »

- [ ] `HF_HOME` (ou équivalent) résolu depuis la configuration, jamais en dur.
- [ ] `models/` ajouté au `.gitignore`.
- [ ] `just fetch-models` livrée, documentée dans le README, **hors de `just check`**.
- [ ] La garde pose `HF_HUB_OFFLINE=1` et rattrape l'erreur en message actionnable.
- [ ] Le smoke tourne **sous la garde** (coordination avec `l1-03.4`).
- [ ] README : une ligne dans le démarrage — « `just fetch-models` avant le premier `just check` ».

## Oracle / recette (figé AVANT implémentation)

| # | Critère mesuré | Seuil de succès |
|---|---|---|
| O1 | `just check` sur une machine dont le cache est **peuplé**, réseau coupé | **vert** |
| O2 | Cache vidé (ou `HF_HOME` pointé sur un dossier vide), un `embed` lancé | échec **immédiat**, message nommant **le `model_id`** ET **`just fetch-models`** (assertion littérale sur les deux chaînes). Vérifié **une fois à la main**, consigné en une ligne de prose |
| O3 | `just fetch-models` sur cache vide, avec réseau | les poids des deux modèles arrivent dans `models/`, **taille totale mesurée et publiée** dans le Résumé |
| O4 | Aucune recette du gate ne fait de réseau | `just check` ne contient ni `fetch-models` ni équivalent — vérification par lecture du justfile |

**Non testé par cette fiche** : le comportement en cas de cache **partiellement** peuplé
(un modèle présent, l'autre non) — cas déclaré non couvert, il produira l'erreur de O2 pour
le modèle manquant · les quotas Hugging Face.

## Notes / pistes

⚠ **Politique de test du lot** : O2 est une **vérification ponctuelle**, pas un test
permanent. Casser une garde une fois pour voir si elle mord est un geste qu'on consigne en
prose ; en faire une machinerie est exactement le travers relevé sur le Lot 0
(8 413 lignes de test pour 4 074 de source).

Le volume des poids est à publier : c'est une donnée d'exploitation utile (place disque, et
temps de préparation d'un worktree d'agent).
