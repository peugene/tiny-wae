Fiche de backlog : sert de brief (prompt) pour l'IA. Révisée post-revue v1 (K-04, K-10, C-4, C-14, C-27) : le fetch et le cache sont partis en l1-00 ; cette fiche ne porte QUE la garde au run. Le propriétaire de la variable est tranché : le code de production, jamais le script de smoke. Révisée post-revue v3 (V-04, C-9/E-22, V-13) : poser la variable « avant tout accès » ne suffit pas — elle est lue à l'import de huggingface_hub ; le grep de la DoD était non scopé et condamnait des appels légitimes ; le README sort du périmètre (zone fermée).

Objectif

Garantir qu'aucun poids ne se télécharge pendant un run. Un téléchargement au milieu d'un run chronométré fausse le banc sans se voir ; un gate dépendant du réseau échoue hors ligne ; chaque worktree d'agent retéléchargerait.

Contexte et périmètre

Grâce à l1-00, les trois artefacts (ckpt Clay, teacher timm, poids TerraMind) passent par huggingface_hub : une seule variable les couvre tous.

À livrer :

  • ⭐ La garde est posée par le CODE DE PRODUCTION : le chemin de résolution des poids (commun aux deux adapters — l'extraire ici en une petite fonction adapters/model_files.py si besoin) rattrape l'erreur du hub pour la réécrire : « poids <model_id> absents du cache — lance just fetch-models ». ⚠ Pourquoi pas le script de smoke : si c'était lui qui posait la variable, retirer la garde du code ne ferait plus tomber le smoke — le mécanisme s'annulerait (revue C-14).
  • ⭐ Le mécanisme, dans cet ordre — corrigé en revue v3 (V-04). « Poser HF_HUB_OFFLINE=1 avant tout accès » est insuffisant : huggingface_hub.constants calcule HF_HUB_OFFLINE et HF_HUB_CACHE à l'import du paquet. Si terratorch, timm ou claymodel a déjà été importé — ce qui arrive dès qu'un adapter est chargé — poser la variable ensuite est un no-op silencieux. Trois niveaux, du plus robuste au filet : 1. cache_dir= et local_files_only=True explicites sur nos appels (hf_hub_download) : indépendants de l'ordre d'import, c'est le seul mécanisme réellement fiable ; 2. variables d'environnement posées avant l'interpréteur — activation pixi et ci.yml (l1-07) : c'est le seul levier sur les appels internes de timm et terratorch, qui ne reçoivent pas nos kwargs ; 3. assertion runtime au moment de résoudre les poids : huggingface_hub.constants.HF_HUB_OFFLINE is True et HF_HUB_CACHE sous hf_home — elle ne prévient pas le défaut, elle le détecte franchement au lieu de le laisser filer en téléchargement silencieux. (Le Lot 0 avait résolu le problème équivalent avec _is_offline() relu à chaque appel : même leçon, autre paquet.)
  • La propriété qui compte : un poids manquant échoue franchement, jamais de téléchargement en douce.
  • ⭐ Code de sortie du cas « poids absent du cache » : USAGE (2) — tranché ici, dans la fiche qui possède le chemin commun (revue v4, m3 : le cas traversait l1-02.3, l1-07 et l1-03.4 sans qu'aucune ne le fixe). Motif : cli/exit_codes.py fige 1 = échec métier, 2 = erreur config/usage, 3 = **non concluant (amont injoignable). Un cache non peuplé n'est pas un échec de traitement et n'est pas un amont injoignable — c'est un **défaut d'environnement**, dont la réparation est une commande (just fetch-models). C'est exactement2`.
  • Le smoke (l1-03.4) tournera sous cette garde sans rien poser lui-même : c'est lui qui l'exercera à chaque just check. Aucun test dédié à la garde (décision de méthode du lot).

Hors périmètre : fetch-models et le cache (l1-00, livrés) · le smoke (l1-03.4) · la vérification manuelle cache-vidé (une seule, en l1-03.4/O4 — pas ici, revue C-27).

Définition de « terminé »

  • [ ] La garde vit dans le code de production, posée avant toute résolution de poids.
  • [ ] Message d'erreur actionnable nommant model_id ET just fetch-models, avec le code de sortie USAGE (2) — importé de cli/exit_codes.py, jamais réécrit en littéral.
  • [ ] Les deux adapters passent par ce chemin commun — grep scopé à src/ : aucun hf_hub_download hors de lui. ⚠ Exceptions légitimes, nommées : scripts/fetch_models.py (dont c'est la raison d'être) et scripts/check_cache.py, tous deux livrés par l1-00. Ils échappent à la garde par construction — un grep non scopé les condamnerait à tort.
  • [ ] Assertion runtime des constantes HF au moment de résoudre les poids.
  • [ ] ⛔ Retirer le bloc [tool.deptry.per_rule_ignores] DEP002 posé par l1-00 — c'est cette fiche qui en est propriétaire. Au moment où elle livre, les quatre paquets (torch, claymodel, terratorch, huggingface_hub) sont réellement importés depuis src/ : la garde n'a plus lieu d'être, et laissée en place elle masquerait les vraies dépendances mortes du reste du projet. deptry doit être vert sans elle — c'est l'oracle O6.
  • [ ] La ligne de README (« just fetch-models avant le premier just check ») est rédigée dans le Résumé, pas appliquée — README.md est hors zone (décision Philippe du 25/08). ⚠ Vaut aussi pour l1-07, qui a une ligne à y reporter.
