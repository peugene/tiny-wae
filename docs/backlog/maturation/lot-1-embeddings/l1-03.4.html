Fiche de backlog : sert de brief (prompt) pour l'IA.

Objectif

Un seul smoke pour tout le lot : il traverse la chaîne réelle — chargement du chip, modèle réel, écriture du vecteur — sur 2 fixtures, hors ligne, en quelques secondes. Il remplace une dizaine de tests d'intégration.

Contexte et périmètre

scripts/smoke.py — le fichier existe déjà (Lot 0). Cette fiche y ajoute une étape, elle ne le réécrit pas. Le smoke d'ingestion reste en place.

⭐ Le smoke tourne SOUS la garde réseau des poids (HF_HUB_OFFLINE=1, cf. l1-02.3). C'est la décision de méthode du lot : on ne teste pas la garde, on met le smoke dessous. Si quelqu'un retire la garde ou casse le chemin du cache, le smoke tombe — à chaque just check, gratuitement, sans une seule ligne de test dédiée.

Ce que fait l'étape ajoutée, sur 2 fixtures de l1-01.4 :

  1. charge le tenseur, embedde avec un vrai modèle (Clay par défaut), écrit le vecteur ;
  2. relance : vérifie que rien n'est recalculé ;
  3. écrit tout dans un TemporaryDirectory — jamais dans ./data ni dans le corpus.

Hors périmètre : toute mesure de performance — le smoke est un contrôle de bon fonctionnement, pas un banc. Les chronomètres sont en l1-04.1.

Définition de « terminé »

  • [ ] scripts/smoke.py étendu, l'étape Lot 0 intacte.
  • [ ] HF_HUB_OFFLINE=1 posé par le script, restauré en sortie (patron TINY_WAE_OFFLINE du Lot 0).
  • [ ] Sorties dans un répertoire temporaire.
  • [ ] just check inclut toujours just smoke — rien à changer au justfile.
  • [ ] Durée de l'étape mesurée et publiée dans le Résumé (elle entre dans le temps du gate).

Oracle / recette (figé AVANT implémentation)

# Critère mesuré Seuil de succès
O1 just smoke, machine hors ligne, cache peuplé vert ; 2 vecteurs écrits, formes et dtypes attendus, aucun NaN
O2 Second passage dans le même répertoire 0 recalcul, vecteurs identiques au bit près
O3 Cas négatif : une fixture retirée rouge, STDERR nommant le chemin du fichier manquant (assertion littérale)
O4 ⭐ Garde réseau : cache vidé, smoke relancé rouge, message nommant le modèle et just fetch-models — aucune requête émise. Vérifié une fois à la main, consigné en une ligne de prose
O5 Durée de l'étape embed du smoke publiée dans le Résumé. Pas de seuil : c'est une information d'exploitation, pas un critère
O6 just check complet vert, hors ligne

Non testé par cette fiche : les performances (l1-04) · la qualité (l1-05) · le comportement avec TerraMind — le smoke n'utilise qu'un modèle, pour rester rapide ; c'est un choix assumé et déclaré.

Notes / pistes

⚠ Attention au temps du gate. Un modèle réel sur 2 chips peut coûter plusieurs secondes, et just check est lancé à chaque fiche par chaque agent. Si l'étape dépasse ~30 s, le signaler dans le Résumé : il faudra soit réduire à une fixture, soit basculer le smoke sur le double et déplacer le modèle réel hors du gate. Mesurer avant de décider.

⚠ Politique de test : le smoke est le test. Ne pas lui ajouter une suite de tests unitaires qui vérifieraient qu'il fait ce qu'il fait.
