Contexte

Deux modèles derrière le port de l1-01.3. Critère de comparaison : pouvoir discriminant par seconde de CPU — il n'y a pas d'achat matériel, le lot décide d'un périmètre.

La table des faits — VÉRIFIÉE AU CODE SOURCE (revue v1, 24/08/2026)

Clay v1.5 TerraMind 1.0 small
Variante réelle ⚠ large — seule publiée en v1.5 (dim 1024, depth 24, ~302 M params d'encodeur) small (dim 384, depth 12, ~21 M)
Entrée 256×256, patch 8×8 → 1024 tokens 256×256 accepté (pos-emb interpolés) → 256 tokens
Sortie brute tuple ; CLS = out[0][:, 0, :] → (1024,) liste de 12 tenseurs (B, 256, 384) — la carte HF qui annonce (B, 196, 768) est fausse (copier-coller de la variante base)

⭐ L'asymétrie, dite franchement (finding du réfuteur)

La comparaison est « Clay-large contre TerraMind-small » — ~302 M contre ~21 M de paramètres d'encodeur, 1024 contre 256 tokens. L'ordre de grandeur attendu du rapport de coût CPU est ~50×, dominé par la taille des modèles AUTANT que par les tokens. Cette asymétrie est subie (aucune variante plus petite de Clay v1.5 n'est publiée), pas choisie : le banc publie les deux compteurs de paramètres côte à côte, et le « pouvoir discriminant par seconde » se lit avec cette réserve. (Décision Philippe, arbitrage A de la revue : on garde le duo — mesurer est le travail du banc.)

Décisions portées par ce chapeau (ne pas rouvrir)

  1. TerraMind small (repli tiny : point d'arbitrage de l1-06.H, pas une décision d'implémenteur).
  2. Les deux modèles travaillent en 256×256 — verdict acté par l1-00, la question 224 n'existe plus.
  3. Le port absorbe l'asymétrie de sortie (CLS vs moyenne de patchs) : l'appelant reçoit un vecteur, point.
  4. Aucun téléchargement au run — les 3 artefacts (ckpt Clay, teacher timm, poids TerraMind) passent par hf_hub_download, donc sous HF_HOME/HF_HUB_OFFLINE (l1-00, l1-02.3).
  5. ⚠ On ne compare JAMAIS un vecteur Clay (1024-d) à un vecteur TerraMind (384-d) — espaces différents. Chaque modèle se compare à lui-même dans le temps ; les modèles se comparent par leurs scores.
