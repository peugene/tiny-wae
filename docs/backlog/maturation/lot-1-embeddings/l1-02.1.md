### La recette, vérifiée au code source (24/08/2026) — suivre, ne pas redécouvrir

1. **Chargement** : ckpt via `hf_hub_download("made-with-clay/Clay", "v1.5/clay-v1.5.ckpt")`
   (cache `l1-00`), puis `ClayMAEModule.load_from_checkpoint(ckpt, model_size="large",
   mask_ratio=0.0, shuffle=False, metadata_path=<chemin ABSOLU du metadata.yaml embarqué>)`.
   - ⚠ **`mask_ratio=0.0` est LE point critique** : le défaut est **0.75 et s'applique en
     inférence** (`mask_out` inconditionnel) — sans cet argument, l'embedding ne voit que le
     quart bas de l'image et tous les tests passent quand même.
     ⚠ **Précision revue v3 (A-3)** : le tutoriel pose en réalité **quatre** arguments —
     `mask_ratio=0.0`, `shuffle=False`, plus `dolls=[16, 32, 64, 128, 256, 768, 1024]` et
     `doll_weights=[1]*7`. Comme les kwargs de `load_from_checkpoint` **priment** sur les
     hyperparamètres restaurés du ckpt, omettre `dolls`/`doll_weights` n'est neutre que si
     le ckpt v1.5 porte les mêmes valeurs : **le vérifier après chargement et le consigner**,
     plutôt que de le supposer.
   - ⚠ `metadata_path` : le défaut est relatif au CWD — embarquer le YAML (ou le résoudre
     depuis le paquet) et passer un chemin absolu, sinon le CLI casse selon d'où on le lance.
   - ⚠ `save_hyperparameters()` restaure les hyperparamètres du ckpt : vérifier APRÈS
     chargement que `model.model.encoder.mask_ratio == 0.0` (assertion dans l'adapter).
2. **Normalisation** : z-score sur **DN** — `(pixels - mean) / std`, stats de
   `metadata.yaml` (`sentinel-2-l2a`, blue: mean 1105., std 1809.), **lookup par nom**
   depuis `BAND_ORDER_EMBED`. Pas de réflectance.
3. **Datacube** : `{"pixels": …, "time": [B,4], "latlon": [B,4], "gsd": tensor(20.0),
   "waves": …}` — time et latlon encodés **comme dans le tutoriel embeddings**
   (sin/cos de la semaine et de l'heure ; sin/cos de lat/lon) depuis `chip.datetime` et
   `chip.lat/lon` ; **`gsd=20`** (le metadata dit 10, notre tenseur est à 20 — lui mentir
   fausserait l'encodage de position) ; `waves` en **µm** (l'unité du code d'entraînement),
   lookup par nom.
   ⭐ **Fait vérifié au code source (revue v3, V-17) — conséquence lourde pour le Lot 2** :
   `time` vaut exactement `np.hstack((week_norm, hour_norm))` (`claymodel/datamodule.py`,
   confirmé par le tutoriel : « `time: batch x 4` — horizontally stacked `week_norm` &
   `hour_norm` »). **Ni l'année, ni aucune époque absolue n'entre dans le modèle.** Ce n'est
   donc pas la date qui est encodée, c'est la **phase saisonnière** : deux acquisitions à un
   an d'écart, à la même semaine, sont **indiscernables** pour le modèle sur ce canal — et
   deux dates de saisons différentes sont écartées par construction, ce qui est exactement
   le confondant que `l1-05.4` cherche à isoler. À consigner au Résumé.
4. **Sortie** : `out = encoder(datacube)` → tuple ; CLS = `out[0][:, 0, :]` → `(1024,)`
   float32.
5. ⚠ L'import de `claymodel` exécute `torch.set_float32_matmul_precision("medium")` au
   niveau module — le consigner dans le Résumé (le banc lancera un processus par modèle).

**Hors périmètre** : fine-tuning · variante tuiles · mesures · la garde offline (`l1-02.3` —
mais résoudre les poids via `hf_hub_download` local, jamais d'URL directe).
