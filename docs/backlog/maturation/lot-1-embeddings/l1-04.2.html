Fiche de backlog : sert de brief (prompt) pour l'IA. Révisée post-revue v3 (S-8, V-09, V-20) : dépend de l1-02.4 — publier un écart « sur le total » exige qu'un vrai modèle existe, sinon le dénominateur est celui du double et l'écart relatif est faux d'un ordre de grandeur.

⛔ Fiche de mesure CPU — ne se dispatche JAMAIS en parallèle d'une autre fiche de banc (l1-04.3a, l1-04.3b, l1-04.4, l1-05.2) ni d'aucune charge CPU concurrente. Le critère habituel « fichiers disjoints » ne protège rien ici : ces fiches écrivent bien dans des scripts distincts, mais elles se disputent les mêmes cœurs, et c'est précisément la grandeur qu'elles mesurent. Le champ concurrent_load du JSON doit dire ce qui tournait à côté — « rien », dans le cas nominal.

Objectif

Chiffrer ce que coûte la lecture du corpus à travers le montage Windows de WSL2, et ce qu'on gagnerait à copier l'échantillon dans le système de fichiers natif. C'est le levier le moins cher du lot : s'il est significatif, il s'applique sans toucher au modèle.

Contexte et périmètre

scripts/bench_io.py — un script, pas un module de production.

Le corpus vit sur D:\datas\tiny-wae, atteint depuis WSL2 en /mnt/d/... via drvfs. Le Lot 0 a déjà mesuré ce que cette couche coûte : just install y recopiait 696 Mo faute de liens durs. Une passe complète sur les embeddings, c'est ~16 Gio à lire à travers elle.

Protocole, à respecter strictement pour que la comparaison veuille dire quelque chose :

  1. prendre l'échantillon de banc gelé par l1-04.1 — pas un échantillon choisi ici : c'est ce qui rend les quatre leviers comparables entre eux ;
  2. mesurer la phase load de l1-04.1 depuis /mnt/d ;
  3. copier l'échantillon dans un répertoire du système de fichiers natif (~/), mesurer à nouveau ;
  4. ⚠ vider le cache disque entre les deux mesures, ou faire les deux mesures plusieurs fois en alternance — sinon on mesure le cache du système, pas le montage. Dire dans le Résumé laquelle des deux méthodes a été retenue.

Hors périmètre : toute modification du pipeline · l'automatisation d'une copie locale (si le levier est significatif, la décision d'en faire une étape appartient à l1-06.H) · le NAS, qui n'est pas utilisé ici.

Définition de « terminé »

  • [ ] scripts/bench_io.py livré, lançable par just script bench_io.
  • [ ] Les deux mesures effectuées sur le même échantillon, protocole documenté.
  • [ ] Écart publié en pourcentage et en valeur absolue, sur la phase load et sur le total — le total étant mesuré avec un vrai modèle (d'où la dépendance à l1-02.4).
  • [ ] Le JSON porte le CV de l1-04.1::stability et son verdict (stable / bruitée / non concluante), plus concurrent_load.
  • [ ] Extrapolation à 5 793 chips écrite noir sur blanc.

Oracle / recette (figé AVANT implémentation)

# Critère mesuré Seuil de succès
O1 Les deux mesures portent sur le même ensemble d'item_id — celui de l1-04.1 ensembles identiques — vérifié dans le script, pas supposé
O2 Le protocole anti-cache est appliqué le JSON porte cache_policy et la série brute des mesures individuelles, horodatées, dans l'ordre d'exécution (≥ 3 alternances) — l'alternance se LIT dans les données, elle n'est pas seulement déclarée
O3 Écart drvfs ↔ natif sur la phase load publié, avec la méthode. Aucun seuil : c'est une mesure
O4 Extrapolation temps de lecture des 5 793 chips dans les deux cas, avec le dénominateur (N chips mesurés) et la mention explicite que c'est une extrapolation linéaire, donc optimiste

Non testé par cette fiche : le comportement sur un autre montage (NAS, SSD externe) · l'effet du cache page de Windows, hors de portée · le gain réel après copie, qui dépendrait du temps de copie lui-même — à mentionner s'il est du même ordre que le gain.

Notes / pistes

⚠ Le piège de cette fiche est le cache disque. Mesurer /mnt/d puis la copie locale juste après revient souvent à mesurer deux fois le cache — et à conclure « aucune différence ». L'alternance répétée est la parade la plus simple sur WSL2, où vider le cache proprement demande des droits.

⚠ Si le gain est négligeable, c'est un excellent résultat : il élimine une hypothèse et le rapport peut le dire en une ligne. Un levier mesuré nul est un levier utile.

⚠ Politique de test : aucun test unitaire. C'est un script de mesure ; sa correction se juge sur le protocole, pas sur des assertions. ⚠ ⭐ « Pas de test » ne veut PAS dire « hors du filet » (revue v4, m2) : pyproject.toml:146 pose files = ["src", "tests", "scripts"] — mypy --strict couvre scripts/, ce script compris. Annotations complètes exigées, comme dans src/. (Et assert y est permis : l1-00 pré-pose l'exemption S101 pour scripts/bench_*.py.)
