# [l1-03.3] — Le backfill des embeddings

> Fiche de backlog : sert de **brief (prompt)** pour l'IA.

## Objectif

Passer les 25 sites en une commande, avec un pool de workers, une reprise naturelle et une
interruption qui ne laisse rien de cassé. C'est l'outil qui produira réellement le corpus de
vecteurs pour `l1-05`.

## Contexte et périmètre

`src/tiny_wae/cli/embed_backfill.py`.

⚠ **Lire `cli/backfill.py` du Lot 0 avant d'écrire** — le patron existe : pool, isolation
par site, distinction entre échec métier et amont injoignable, compteurs agrégés. Ici c'est
plus simple : pas de réseau, donc pas de cas « injoignable ».

Interface :

```
just run embed-backfill --model clay-v1.5 [--sites A01,B09] [--workers N] [--from …] [--to …]
```

Points d'attention :

- ⭐ **Le parallélisme sur CPU n'est pas gratuit ici.** Contrairement au backfill du Lot 0,
  qui attendait le réseau, celui-ci est **limité par le calcul** : N workers se disputent
  les mêmes cœurs, et chaque worker peut lui-même lancer plusieurs threads BLAS.
  **Sur-paralléliser peut ralentir.** Le défaut doit être **prudent** (workers = 1 ou 2), et
  la mesure du bon réglage appartient à `l1-04.3` — cette fiche fournit le levier, pas sa
  valeur.
- **L'isolation par site** reste la bonne granularité : un site en échec n'empêche pas les
  autres.
- **La reprise est naturelle** : l'idempotence de `l1-03.2` fait qu'un relancement saute ce
  qui existe. Aucun fichier d'état à maintenir.
- **Interruption (SIGINT)** : sortie non nulle, et **tous les vecteurs écrits restent
  relisibles** — c'est l'écriture atomique de `l1-03.1` qui le garantit.

**Hors périmètre** : la campagne réelle elle-même (elle sera lancée par `l1-05.3`) · les
mesures de débit (`l1-04`) · le choix du nombre de workers (`l1-04.3`).

## Notes / pistes

⚠ **Ne pas transposer aveuglément le backfill du Lot 0.** Là-bas, 6 workers étaient bons
parce que le goulot était le réseau. Ici le goulot est le CPU, et un modèle PyTorch utilise
déjà plusieurs threads : **6 workers × N threads = contention**. C'est un piège classique et
il se mesure, il ne se devine pas.

⚠ **Politique de test** : tout se teste sur le double. Le test d'interruption (O4) est celui
qui a le plus de valeur — ne pas le sacrifier au profit de tests de compteurs, qui sont plus
faciles à écrire et attrapent beaucoup moins.
