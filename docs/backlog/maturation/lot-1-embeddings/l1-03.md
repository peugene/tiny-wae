# [l1-03] — CHAPEAU : produire et ranger les vecteurs

> **Fiche chapeau : elle ne se dispatche pas.** Révisée post-revue v1.

## Contexte

Ce chapeau transforme les adapters en **outil exploitable** : un CLI qui parcourt les chips
d'un site, calcule leurs vecteurs, les range, et **ne recalcule rien** si on le relance.

Il reprend tel quel le patron des CLIs du Lot 0 — codes de sortie du chapeau `l0-01`,
logs sur STDERR / données sur STDOUT ou fichiers, compteurs avec dénominateur, pool de
workers et reprise pour le backfill. **Ne pas réinventer : lire `cli/ingest.py` et
`cli/backfill.py` avant d'écrire.**

⭐ **Ce chapeau peut être écrit et vérifié entièrement avec le double `FakeEmbeddingModel`**
de `l1-01.3` — donc sans poids, sans réseau, en millisecondes. C'est ce qui le rend
parallélisable avec `l1-02`. Seule `l1-03.4` a besoin d'un vrai modèle.

## Décisions portées par ce chapeau (ne pas rouvrir)

1. **Stockage fichier, pas de base.** pgvector ouvre le Lot 2. Un fichier de vecteurs plus
   un compagnon de métadonnées suffisent à mesurer et à alimenter la suite.
2. ⭐ **Clé d'idempotence : `grid_hash` + `model_id` + `spec_hash`** — et le `spec_hash`
   entre AUSSI dans le **nom du fichier** (revue K-20) : produire une autre variante de
   spec **ajoute** des vecteurs à côté, n'écrase rien. C'est ce qui rend la décision
   « un vecteur par chip » réellement réversible.
3. **Filtrage à l'entrée** : seuls les chips dont le `cloud_pct` est ≤ `embed_cloud_pct_max`
   sont embeddés. Valeur par défaut **10**, **dans `settings.yaml`** — jamais une constante.
   Justification chiffrée : sur les 5 793 chips ingérés, la médiane du `cloud_pct` est
   **0,0 %** et 86 % sont sous 10 % ; le seuil d'ingestion à 30 % est une porte large que
   presque personne ne franchit.
4. **Le compagnon est défini UNE fois, dans `l1-03.1`** (dataclass `VectorMeta`) — les
   autres fiches y renvoient sans énumérer (revue C-10). Il porte le contexte du Lot 2,
   y compris `blas_threads` et `torch_version` (revue C-12 : sans eux, le Lot 2 comparerait
   des vecteurs de configurations différentes « sans le savoir »).

## Politique de test (rappel — c'est un POC)

Tout ce chapeau se teste avec le **double**, sur les 4 fixtures. Ce qui mérite un test :
l'idempotence (dans les deux sens), le filtrage (dans les deux sens), les codes de sortie.
Ce qui n'en mérite pas : les valeurs de vecteurs, les combinaisons exhaustives d'options.
**Un seul smoke** pour toute la chaîne (`l1-03.4`).
