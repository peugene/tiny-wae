# [l1-03.2] — Le CLI `embed`

> Fiche de backlog : sert de **brief (prompt)** pour l'IA.

## Objectif

Parcourir les acquisitions d'un site sur une fenêtre, calculer les vecteurs manquants, les
ranger, et **ne rien recalculer** au second passage.

## Contexte et périmètre

`src/tiny_wae/cli/embed.py`.

⚠ **Lire `cli/ingest.py` avant d'écrire.** Ce CLI en est le frère : mêmes codes de sortie
(chapeau `l0-01` : `0` succès · `1` échec métier · `2` usage/config · `3` non concluant),
logs sur **STDERR**, résumé de compteurs, aucune donnée mélangée aux logs.

Interface :

```
just run embed --site A01 --from 2024-01-01 --to 2024-12-31 --model clay-v1.5 [--force]
```

Comportement :

- parcourt `<data_root>/<site>/*/manifest.json`, retient les `status == "ingested"` dans la
  fenêtre ;
- ⭐ **écarte** ceux dont `cloud_pct > embed_cloud_pct_max` (défaut **10**, lu de
  `settings.yaml`) et les **compte** dans un compteur dédié `skipped_cloud` ;
- pour chacun : charge le tenseur (`l1-01.2`), embedde (`l1-01.3` → adapter), écrit
  (`l1-03.1`) ;
- ⭐ **saute** ceux dont la clé d'idempotence stockée égale la clé courante → `skipped`.
  `--force` recalcule quand même ;
- compte et publie : `found`, `skipped_cloud`, `embedded`, `skipped`, `failed`, avec
  **le dénominateur**.

⭐ **Invariant de conservation, sur le modèle du Lot 0** :
`found == skipped_cloud + embedded + skipped + failed`. Il doit **lever** s'il ne boucle pas.

Le CLI accepte n'importe quel `model_id` du registre — y compris le **double**, ce qui
permet de tout vérifier sans poids.

**Hors périmètre** : le parcours multi-sites (`l1-03.3`) · toute mesure de temps
(`l1-04.1` instrumentera ce code de l'extérieur) · toute qualité.

## Définition de « terminé »

- [ ] `cli/embed.py` livré, découvert automatiquement par `__main__` (mécanisme `l0-01.2`).
- [ ] Codes de sortie conformes au chapeau `l0-01`.
- [ ] Invariant de conservation vérifié à chaque run, levée si rompu.
- [ ] `embed_cloud_pct_max` dans `settings.yaml` **et** surchargeable par variable d'environnement.
- [ ] `tests/test_cli_embed.py` — sur le **double**, avec les fixtures de `l1-01.4`.

## Oracle / recette (figé AVANT implémentation)

| # | Critère mesuré | Seuil de succès |
|---|---|---|
| O1 | Run sur les 4 fixtures avec le **double**, seuil à 10 % | compteurs **exacts, gelés dans le test** ; l'invariant de conservation **boucle** ; un vecteur + un compagnon par item embeddé |
| O2 | ⭐ **Run double** — témoins positif ET négatif | 1er run : `embedded > 0`, `skipped == 0` · 2e run : `embedded == 0`, `skipped == embedded du 1er`, **vecteurs identiques au bit près**. Sans le témoin positif, un CLI qui ne ferait rien passerait |
| O3 | `--force` au 2e run | recalcule tout : `embedded` retrouve sa valeur du 1er run |
| O4 | ⭐ **Filtre nuage, dans les deux sens** | la fixture à `cloud_pct` > 10 est en `skipped_cloud` et **n'a pas de vecteur** ; avec `embed_cloud_pct_max=100`, elle est embeddée. Le seuil discrimine réellement |
| O5 | `spec_hash` modifié (spec mutée dans le test) | l'item est **ré-embeddé** — c'est ce qui rend la décision « 20 m » réversible |
| O6 | Un item en échec injecté (le double lève sur un id) | manifeste `failed` + cause, les autres traités, **exit 1** ; l'invariant boucle toujours |
| O7 | Site sans aucun chip dans la fenêtre | exit **0**, `found == 0`, message explicite — ce n'est pas une erreur |
| O8 | `just check` | vert, hors ligne |

**Non testé par cette fiche** : le comportement sur les 5 793 chips (`l1-03.3`) · les temps
(`l1-04.1`) · la qualité des vecteurs · la concurrence.

## Notes / pistes

⚠ **Le piège du témoin positif** (O2) est celui que la revue v3 du Lot 0 avait relevé sur
`bytes_downloaded` : un critère « le second run ne fait rien » est satisfait par un CLI qui
ne fait jamais rien. D'où l'exigence `embedded > 0` au premier passage.

⚠ **Politique de test** : pas de matrice d'options, pas de test par combinaison de drapeaux.
Ce qui mérite un test ici, ce sont les **invariants** — conservation, idempotence, filtre —
et chacun dans les deux sens.
