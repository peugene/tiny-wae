# [l1-03.2] — Le CLI `embed`

> Fiche de backlog : sert de **brief (prompt)** pour l'IA.
> **Révisée post-revue v1** (E-1, K-08/S-10, C-24) : dépendances réalignées sur le double
> (plus d'arête vers Clay — c'est ce qui rend le chapeau parallèle à `l1-02`) ; l'oracle
> d'échec ne touche PLUS aux manifestes du Lot 0.
> **Révisée post-revue v3** (V-10, V-16, E-23, A-14) : dépend de `l1-00`, qui **pré-pose**
> les clés de `settings.yaml` (plus d'écriture concurrente) ; l'option `--cloud-max`
> n'était oraclée nulle part alors que deux fiches en dépendent ; la sémantique de reprise
> d'un `.error.json` n'était écrite nulle part.

## Objectif

Parcourir les acquisitions d'un site sur une fenêtre, calculer les vecteurs manquants, les
ranger, et **ne rien recalculer** au second passage.

## Contexte et périmètre

`src/tiny_wae/cli/embed.py`.

⚠ **Lire `cli/ingest.py` avant d'écrire.** Ce CLI en est le frère : mêmes codes de sortie
(ceux du chapeau `l0-01` — renvoi, pas de recopie), logs sur **STDERR**, résumé de
compteurs, aucune donnée mélangée aux logs.

Interface :

```
just run embed --site A01 --from 2024-01-01 --to 2024-12-31 --model clay-v1.5 [--force] [--cloud-max N]
```

Comportement :

- parcourt `<data_root>/<site>/*/manifest.json`, retient les `status == "ingested"` dans la
  fenêtre ;
- ⭐ **écarte** ceux dont `cloud_pct > embed_cloud_pct_max` (défaut **10**) et les **compte**
  dans un compteur dédié `skipped_cloud`. ⭐ **Précédence à trois niveaux, à respecter et à
  oracler** (revue v3, V-16) : `--cloud-max` (option) **>** `TINY_WAE_EMBED_CLOUD_PCT_MAX`
  (env) **>** `settings.yaml`. C'est l'option que la checklist humaine de `l1-05.3.H`
  utilise, et elle n'était exercée par aucun oracle.
  ⚠ **Deux points d'ancrage dans le code existant** (revue v3, V-10/A-5) : la clé est
  **pré-posée par `l1-00`** dans `config/settings.yaml` — cette fiche **consomme**, elle
  n'écrit pas dans ce fichier ; et `embed_cloud_pct_max` doit figurer dans
  `adapters/config_io.py::_INT_FIELDS`, sans quoi la surcharge par environnement rend une
  **chaîne** et le contrôle de bornes de `core/settings.py::validate()` lève un `TypeError`
  illisible au lieu d'une erreur de configuration ;
- pour chacun : charge le tenseur (`l1-01.2`), embedde (`l1-01.3` → adapter), écrit
  (`l1-03.1`) ;
- ⭐ **saute** ceux dont la clé d'idempotence stockée égale la clé courante → `skipped`.
  `--force` recalcule quand même ;
- compte et publie : `found`, `skipped_cloud`, `embedded`, `skipped`, `failed`, avec
  **le dénominateur**.

⭐ **Invariant de conservation, sur le modèle du Lot 0** :
`found == skipped_cloud + embedded + skipped + failed`. Il doit **lever** s'il ne boucle pas.

Le CLI accepte n'importe quel `model_id` du registre — y compris le **double**, ce qui
permet de tout vérifier sans poids.

⭐ **Sémantique de reprise d'un `.error.json`** (revue v3, E-15 — n'était écrite nulle
part) : un `.error.json` est une **trace de diagnostic**, jamais un marqueur de skip. Un
run suivant **rejoue** l'item comme s'il n'y avait rien, et **supprime** le fichier d'erreur
en cas de succès. La règle inverse — traiter l'erreur comme « déjà traité » — produirait un
corpus incomplet **silencieusement**, avec des compteurs qui bouclent : exactement le type
de défaut que l'invariant de conservation ne peut pas attraper.

⭐ **Taxonomie des CLI** : `src/tiny_wae/__main__.py` déclare en docstring une « taxonomie
fermée du lot (9 sous-commandes) ». Le Lot 1 la porte à 15 : **c'est cette fiche, premier
CLI ajouté, qui met la docstring à jour** — les suivantes n'y touchent plus. Aucun test ne
l'asserte aujourd'hui ; ne pas en écrire un pour ça, c'est de la documentation.

**Hors périmètre** : le parcours multi-sites (`l1-03.3`) · toute mesure de temps
(`l1-04.1` instrumentera ce code de l'extérieur) · toute qualité.

## Notes / pistes

⚠ **Le piège du témoin positif** (O2) est celui que la revue v3 du Lot 0 avait relevé sur
`bytes_downloaded` : un critère « le second run ne fait rien » est satisfait par un CLI qui
ne fait jamais rien. D'où l'exigence `embedded > 0` au premier passage.

⚠ **Politique de test** : pas de matrice d'options, pas de test par combinaison de drapeaux.
Ce qui mérite un test ici, ce sont les **invariants** — conservation, idempotence, filtre —
et chacun dans les deux sens.
