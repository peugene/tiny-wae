# [l1-01.3] — Le port derrière lequel les modèles se branchent

> Fiche de backlog : sert de **brief (prompt)** pour l'IA.
> **Révisée post-revue v1** (K-22, S-7, C-8, E-23, D-19) : signature élargie à `ChipTensor`,
> imports paresseux, table du registre pré-posée pour supprimer l'écriture concurrente.

## Objectif

Définir le contrat que Clay et TerraMind respecteront, et le registre qui résout un
`model_id`. Le port promet **« un vecteur par chip »** ; l'asymétrie de sortie (Clay : CLS
1024-d · TerraMind : liste de couches → moyenne des 256 patchs 384-d) est absorbée par les
adapters — l'appelant ne voit rien.

## Contexte et périmètre

`src/tiny_wae/core/embedding_port.py` (Protocol, pur) et
`src/tiny_wae/adapters/model_registry.py`.

- `EmbeddingModel` — Protocol : `model_id: str` · `spec: EmbeddingSpec` · `dim: int` ·
  ⭐ `embed(chip: ChipTensor) -> np.ndarray` — **le `ChipTensor` entier, pas un tableau
  nu** : Clay a besoin de `datetime`, `lat/lon` et `gsd` (revue K-02c, 8 dimensions du
  modèle leur sont réservées). Un port qui ne passerait que les pixels forcerait les
  adapters à tricher.
- `FakeEmbeddingModel` — dans **`adapters/embed_fake.py`** (emplacement tranché, revue
  D-19) : déterministe (hash de l'entrée → vecteur), zéro torch. ⭐ **Sa spec inclut ce que
  ses consommateurs exigent** (revue v2, m2) : `fail_on: set[str]` (lève une erreur typée
  sur ces `item_id` — requis par `l1-03.2`/O6 et `l1-03.3`/O2), `delay_s: float` (ralentit
  chaque embed — requis par le jalon SIGINT de `l1-03.3`/O4 **et par `l1-04.1`/O1**, qui
  s'en sert pour vérifier que ses chronomètres séparent bien les phases), et une
  **notification de progression** (callback ou compteur exposé — c'est elle que le test
  SIGINT attend avant d'interrompre). C'est lui qui découple le chapeau `l1-03` des vrais
  modèles. ⭐ **Ces trois capacités s'oraclent ICI, chez leur propriétaire** (O7, revue v3
  C-20) — un consommateur qui découvre à l'usage que le double ne sait pas faillir a déjà
  perdu son temps.
- ⭐ **Registre : table statique COMPLÈTE, imports PARESSEUX** (revue S-7/K-22) :

  ```python
  _ADAPTERS = {
      "fake": ("tiny_wae.adapters.embed_fake", "FakeEmbeddingModel"),
      "clay-v1.5": ("tiny_wae.adapters.embed_clay", "ClayModel"),
      "terramind-v1-small": ("tiny_wae.adapters.embed_terramind", "TerraMindModel"),
  }
  ```

  Les **trois entrées sont écrites ICI, maintenant** — les modules n'existent pas encore,
  et c'est voulu : `l1-02.1` et `l1-02.2` ne touchent **que leur propre fichier**, plus
  aucune écriture concurrente sur le registre. `resolve_model` fait
  `importlib.import_module` **dans la fonction** : importer le registre n'importe pas
  torch, un module manquant donne une erreur claire listant les ids disponibles.

**Hors périmètre** : les vrais adapters (`l1-02`) · torch (jamais importé au chargement).

| # | Critère mesuré | Seuil de succès |
|---|---|---|
| O1 | Substituabilité statique : fonction annotée `EmbeddingModel` recevant le double | `mypy --strict` vert **sans cast ni type: ignore** — mypy est l'oracle (leçon out-01) |
| O2 | `FakeEmbeddingModel.embed` deux fois sur le même `ChipTensor` | vecteurs identiques, forme `(dim,)`, float32 |
| O3 | `resolve_model("inconnu")` | erreur typée **listant les 3 ids** (assertion littérale) |
| O4 | ⭐ **Dans un sous-processus frais** (`subprocess.run([sys.executable, "-c", …])`) : `import tiny_wae.__main__` puis assertion | **`"torch" not in sys.modules`**. C'est ce qui garantit que `l1-03.2`, `l1-03.3` et `l1-04.1` trouveront un double capable de ce qu'ils lui demandent |
