# [l1-01.3] — Le port derrière lequel les modèles se branchent

> Fiche de backlog : sert de **brief (prompt)** pour l'IA.

## Objectif

Définir le **contrat** que Clay et TerraMind devront respecter, et le registre qui résout un
`model_id` en implémentation. Sans ce port, chaque appelant connaîtrait les particularités de
chaque modèle — et il y en a, précisément là où on ne les attend pas.

## Contexte et périmètre

`src/tiny_wae/core/embedding_port.py` (le Protocol, pur) et
`src/tiny_wae/adapters/model_registry.py` (la résolution `model_id → adapter`).

⭐ **La raison d'être du port, en une phrase** : les deux modèles n'ont **pas le même
contrat de sortie**. Clay rend **un vecteur** (son embedding de classe) ; TerraMind rend
**196 embeddings de patch de 768 dimensions** qu'il faut agréger. Le port promet
**« un vecteur par chip »** et chaque adapter est responsable de le produire — Clay prend
son CLS, TerraMind moyenne ses patchs. **L'appelant ne voit pas la différence.**

À livrer :

- `EmbeddingModel` — `Protocol` (pas une classe de base) exposant :
  - `model_id: str` — identifiant stable, entre dans la clé d'idempotence ;
  - `spec: EmbeddingSpec` — ce que le modèle attend en entrée (`l1-01.1`) ;
  - `dim: int` — dimension du vecteur produit ;
  - `embed(tensor) -> np.ndarray` — **un vecteur `(dim,)` float32**, pas une matrice.
- `FakeEmbeddingModel` — double de test **substituable**, déterministe (hash de l'entrée →
  vecteur), sans aucune dépendance à torch. Il permet à `l1-03.x` d'avancer **avant** que le
  moindre poids soit téléchargé.
- `resolve_model(model_id) -> EmbeddingModel` — registre. Un `model_id` inconnu lève une
  erreur typée **listant les identifiants disponibles**.

**Hors périmètre** : aucun modèle réel (`l1-02`), aucun chargement de poids, aucun torch.
Cette fiche doit rester importable sans que torch soit installé.

## Définition de « terminé »

- [ ] `core/embedding_port.py` et `adapters/model_registry.py` livrés, `mypy --strict` vert.
- [ ] `EmbeddingModel` est un `Protocol` ; `FakeEmbeddingModel` le satisfait **sans en hériter**.
- [ ] Le registre connaît au moins le double ; les deux vrais modèles s'y ajouteront en `l1-02`.
- [ ] `tests/test_embedding_port.py` — court.

## Oracle / recette (figé AVANT implémentation)

**Non testé par cette fiche** : tout comportement de modèle réel · la pertinence de
l'agrégation choisie par chaque adapter (`l1-02`).

## Notes / pistes

Le double n'est pas une commodité de test : c'est ce qui **découple le chapeau `l1-03`** du
chapeau `l1-02`. Le CLI `embed`, son stockage et son idempotence peuvent être écrits et
vérifiés entièrement avec le double — donc **sans réseau, sans poids, en millisecondes**.
C'est le même patron que `FixtureSource` au Lot 0.

⚠ **Politique de test** : le vrai filet ici est `mypy`, pas pytest — le port est un contrat
statique. Les tests d'exécution ne font que confirmer que le double se comporte comme prévu.
